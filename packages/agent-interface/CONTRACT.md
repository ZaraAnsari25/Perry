# The `shop` command contract

The standard every `shop` implementation must meet, hand-written (`core.ts`) or generated by Droid (`generated/core.ts`). The contract tests (`search.test.ts`, `shop.test.ts`, run with `SHOP_IMPL=generated` for the generated one) check exactly this.

## Entry point

```ts
export async function runShop(
  args: string[],
  ctx: { storeUrl: string; cartId: string },
): Promise<{ stdout: string; stderr: string; exitCode: number }>;
```

`args` are the words after `shop` (e.g. `["cart", "add", "VEL-BLK-08"]`). `runShop` never throws for a bad command or an unreachable store; it returns an exit code.

Facts come from the store's catalog (`apps/storefront/lib/catalog.ts`: `catalog`, `getProduct(slug)`, `findVariant(sku)`), read at call time. The cart is the store's real cart (see "Cart API" below). Every line of stdout and stderr ends with `\n`.

## Exit codes

- **0** success
- **1** the agent's mistake (bad SKU, sold out, already in the cart, wrong flags); the message says what to do next
- **2** a system problem (store unreachable, timeout, unexpected response)

## Commands

| Invocation | Behavior | Exit |
|---|---|---|
| `shop`, `shop help`, `shop --help` | Print usage to stdout, one line per command, containing the texts `shop search`, `shop product`, `shop cart add`, `shop cart show` and `shop checkout --dry-run` | 0 |
| `shop search [filters] [words...] [--json] [--limit N]` | See "search" | 0 / 1 |
| `shop product <slug-or-SKU> [--json]` | See "product" | 0 / 1 |
| `shop cart add <SKU>` | See "cart add" | 0 / 1 / 2 |
| `shop cart add` (no SKU) | stderr `shop: missing SKU. Usage: shop cart add <SKU>` | 1 |
| `shop cart show [--json]` | Print the cart line (see "Cart line") | 0 / 2 |
| `shop checkout --dry-run` | See "checkout preview" | 0 / 2 |
| `shop checkout` (without `--dry-run`) | stderr `shop: checkout needs human approval and is not available to agents. Use --dry-run to preview.` | 1 |
| anything else | stderr starting `shop: unknown command "<args joined by spaces>"`, then usage | 1 |

`--qty N` (or `--qty=N`) anywhere: if N is not `1`, stderr `shop: only quantity 1 per add is supported`, exit 1, nothing sent. `--qty 1` is ignored.

Output is compact: tab-separated rows, no decoration. `--json` prints only JSON (one line) and nothing else on stdout. SKUs are the join key everywhere. Prices print as `$` plus the number (`$98`).

## search

Flags, each as `--flag value` or `--flag=value`, all optional, all generic store facets: `--color <c>`, `--category <c>`, `--min-price <n>`, `--max-price <n>`, `--size <n>`, `--in-stock`, `--limit <n>` (default 20), `--json`. Any other argument not starting with `-` is a free-text word.

A variant **matches** when all of these hold:
- `--color` equals the product's color, case-insensitively; `--category` likewise
- `--min-price n`: price ≥ n; `--max-price n`: price ≤ n
- `--size n`: the variant's size is n; `--in-stock`: the variant's stock > 0
- every word appears, case-insensitively, in the product's name or description

Results are **one row per matching variant**, in catalog order (products in catalog order, variants in their order). `total` is the number of matches; at most `limit` rows are shown.

Text output (default):

```
1 match (showing 1)
VEL-BLK-08	Velocity Runner	black	running	$98	size 8	stock 3
Near misses:
  Tempo Lite: size 8 is sold out
  Cloud Glide: color is navy, not black
```

- First line: `0 matches` when there are none; otherwise `<total> match (showing <shown>)` for one, `<total> matches (showing <shown>)` for more. If `total > shown`, append `; narrow with --max-price or --size`.
- Each row: `SKU`, name, color, category, `$price`, `size N`, then `stock N`, or `sold out` when stock is 0 (only possible without `--in-stock`), separated by tabs.
- **Near misses**, only when there are fewer than 3 matches: products with no matching variant that fail **exactly one** filter, in catalog order, at most 3, after a `Near misses:` line, each as two spaces, the product name, `: ` and the reason. A filter counts as failed once per product: color, category, min price, max price, each word, and the variant filters together (with `--size`, only that size's variant counts; a product without that size fails "size"; if it has that size but it's sold out under `--in-stock`, it fails "stock"). Reasons, exactly:
  - `color is <product color>, not <asked color>`
  - `category is <product category>, not <asked category>`
  - `$<price> is over --max-price <n>`
  - `$<price> is under --min-price <n>`
  - `doesn't mention "<word>"`
  - `no size <n>`
  - `size <n> is sold out` (with `--size`), or `sold out in every size` (without)
- `0 matches` (with any near misses) is a valid answer: exit 0.
- `--json`: only a JSON array of the shown rows, each `{ "sku", "slug", "name", "color", "category", "priceUsd", "size", "stock", "inStock" }` (`inStock` is `stock > 0`). No count line, no near misses.
- Bad input, exit 1 with an error line and usage on stderr: an unknown flag (e.g. `--colour`), a flag missing its value, a non-numeric or negative number, `--limit` that isn't a whole number ≥ 1.

## product

`shop product <slug-or-SKU> [--json]` accepts a product slug or any of its variants' SKUs.

```
Velocity Runner	black	running	$98
A versatile neutral running shoe for everyday training.
size	SKU	stock
7	VEL-BLK-07	2
8	VEL-BLK-08	3
9	VEL-BLK-09	sold out
10	VEL-BLK-10	4
```

- `--json`: one JSON object with the product's catalog fields (`slug`, `name`, `category`, `color`, `priceUsd`, `description`) and `variants`, each `{ "size", "sku", "stock", "inStock" }`.
- Unknown: stderr `shop: no product "<x>". Try shop search.`, exit 1.

## cart add

`shop cart add <SKU>`, in this order:

1. More than one SKU: exit 1 with an error on stderr, nothing sent.
2. `findVariant(sku)` finds nothing: stderr `shop: unknown SKU "<SKU>". Find SKUs with shop search or shop product <slug>.`, exit 1, **no request sent**.
3. Stock is 0: stderr `shop: <SKU> (<name>, size <n>) is sold out.`; then, if any exist, a line `In stock instead:` and up to 3 in-stock alternatives as search rows (same color and same size from other products first, then other in-stock sizes of the same product). Exit 1, **no request sent**.
4. Read the real cart. If it already holds this SKU: stderr `shop: <SKU> is already in the cart (quantity <q>). Not adding it again.`, exit 1, **no POST sent**.
5. POST the product page's add-to-cart form (see "Cart API").
   - 303 redirect whose path is `/cart`: success.
   - 303 redirect with `error=sold-out` in its query, or to `/search`: stderr `shop: <SKU> is sold out or unavailable.`, exit 1.
   - anything else, a network error or a timeout: exit 2.
6. On success, read the real cart again and print `Added <SKU> (<name>, size <n>).` and then the cart line.

## Cart line

The cart as one JSON line: names, sizes and prices from the catalog, quantities from the real cart, items in the store's order:

```
{"items":[{"sku":"VEL-BLK-08","name":"Velocity Runner","size":8,"priceUsd":98,"quantity":1}],"totalUsd":98}
```

An empty cart is `{"items":[],"totalUsd":0}`. `shop cart show` and `shop cart show --json` print the same line.

## checkout preview

`shop checkout --dry-run` reads the real cart and never places an order.
- Empty cart: `Cart is empty; nothing would be ordered.` then `Dry run: no order was placed.`
- Otherwise: `Would order:`, then one line per item, `SKU`, name, `size N`, `qty Q`, `$price each`, `$line total` separated by tabs, then `Total: $<sum>`, then `Dry run: no order was placed.`

## Store problems

Any failure to reach or read the store (network error, timeout, non-2xx cart read, a POST answer that isn't one of the 303s above): stderr starting `shop: could not reach the store (` and a short reason in parentheses, exit 2.

## Cart API

Only ever contact `ctx.storeUrl` (build URLs with `new URL(path, storeUrl)`), each request with a 5-second timeout (`AbortSignal.timeout(5000)`).
- Read: `GET /api/cart?cartId=<cartId>` returns `{ "cartId": "...", "items": [{ "sku": "...", "quantity": n }] }`.
- Add: `POST /api/cart` with form fields `sku=<SKU>` and `slug=<product slug>` (URL-encoded form or multipart form data), header `Cookie: cart_id=<cartId>`, `redirect: "manual"`. The store answers 303 to `/cart` on success, or 303 to `/products/<slug>?error=sold-out` or `/search` when unavailable. Adding the same SKU twice would make quantity 2, which fails verification; step 4 above prevents that.

Refusals never change the cart. Nothing places an order.
